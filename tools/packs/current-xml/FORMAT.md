# Original wikitext engineering capsules, version 1

This separate format consumes MediaWiki export 0.11 XML, including concatenated bzip2 members. It does not consume or replace the historical rendered-HTML producer formats. There is no production admission or promotion operation.

A capsule is an immutable SQLite database (user_version 541), receipt and optional exported original text. Each source/page/revision identity retains page, revision and contributor fields, namespace, redirect, timestamp, content model/format, availability and unverified publisher SHA1. The lexical XML text payload is stored once, compressed with zlib; XML entities and CDATA decode to inspectable wikitext. CRLF and Unicode scalar sequences are preserved from the archive lexical text. This is not a claim about pre-publisher source bytes. XML ranges are half-open byte coordinates in the decoded XML stream; search ranges are half-open UTF16 coordinates in decoded wikitext, never compressed-file offsets. The capsule stores no duplicated whole-body search index (FTS bytes zero).

Search is a bounded case-sensitive literal scan of complete retained original wikitext and metadata titles, with stable source/page/revision IDs. It is appropriate only for these <=64 MiB engineering shards, not million-article retrieval. Title hits are metadata, not factual support. Inspection returns the complete original text, including templates, references, math and tables, without executing or rendering markup. Export uses fixed filenames and exact UTF8 bytes plus source metadata; hostile titles never become paths.

The parser retains at most one bounded page, limits text/page/token/depth/revision/aggregate bytes and checks cancellation/deadline during input, decompression, callbacks and SQL. It rejects DTD/entity declarations, wrong namespaces, malformed XML, conflicting identical revision IDs and unknown layouts. Missing/deleted text and unsupported content models have explicit non-searchable dispositions. All revisions remain separate; this is not a latest-revision census. Duplicate equivalence includes metadata and original text but not occurrence coordinates. Duplicate occurrences remain in the disposition ledger.

A transaction either commits a complete engineering input or an explicitly requested bounded prefix; errors roll back and leave a non-readable failed staging artifact. Existing outputs are never replaced. Prefix reads charge all bytes returned by read(), including decoder read-ahead, and retain a SHA256 of only those compressed bytes. They do not verify the full archive digest, publisher text SHA1, complete XML validity, rights, freshness or article census. A page cap discards buffered continuation; incomplete page and decoded tail counters are explicit.

No offline Android reader/import/runtime qualification, rendered fidelity, rights clearance, factual-answer eligibility or complete 12GB/50GB profile follows. All records remain inspection-only or explicitly unavailable/unsupported. Host archive storage is separate from hypothetical installed assets; temporary transaction, capsule, export and rollback bytes must be counted independently. Existing complete-source and structure contracts remain unchanged.

# Indexed engineering derivative, version 542

`indexed.py build` reads an existing immutable 541 capsule and creates a new 542 capsule without changing any original record, lexical blob or provenance field. A Unicode-scalar trigram dictionary uses exact UTF8 BLOB keys with no normalization; WITHOUT ROWID `(term, ordinal)` postings contain no copied body. Stable ordinals follow `(page, revision)`. Ordinary installed SQLite B-trees suffice; no host FTS5 or Android tokenizer support is assumed.

Queries require 3–256 scalars. They bind SQL parameters, never MATCH syntax. The rarest trigram seeds up to 256 candidate ordinals; all query grams must occur before exact original-text verification. Body precedes title, first occurrence only, one result per revision, maximum20. False positives across positions/fields are removed by exact verification. Short queries are explicitly refused, without a hidden scan fallback. Incomplete results contain an output/query-bound last-examined ordinal cursor. Opening validates the file hash, schema, counts, index digest and references without decoding original bodies; that startup/index validation cost is separate from query timing.

The 64MiB derivative bound, 262144 unique grams per record, 180s build deadline and 10s query deadline are engineering limits, not corpus qualification. Builds preserve failed staging and prior outputs, and cancellation rolls back. Original inspection/export uses the unchanged 541 decoder/range/hash contract. Index pages, terms, source records, metadata, journal/staging and retained failures count toward actual storage; there is no full-profile size projection or Android runtime claim.
