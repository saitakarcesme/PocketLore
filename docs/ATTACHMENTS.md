# Optional offline photo text and speech

Open **Offline photo text and speech** from the research screen. Typing works without either asset. This feature recognizes English input; it does not reason about images, certify facts, or turn a transcript into cited evidence.

Install `eng.traineddata` for OCR and/or `ggml-tiny.en.bin` for speech using the two asset buttons. Obtain the exact files listed in [models.json](../tools/attachments/models.json), transfer them locally, then select them with Android's file picker. The app verifies size and SHA-256 before atomic replacement. It has no downloader, cloud fallback, platform SpeechRecognizer or Google Play dependency. Both optional assets total 81,817,803 bytes; native engines are packaged in the APK. No extra asset is mandatory for ordinary research.

Choose an image or local WAV, or grant microphone permission and record up to 15 seconds. Tap **Stop recording** to transcribe or **Cancel recognition** to discard. Leaving the screen cancels active work. Review and edit the text before choosing **Use reviewed text as question**; that fills the research question without running it. Denying microphone access leaves typed input and local WAV selection available.

Images are limited to 4 MiB and four million decoded pixels. Decode uses Android BitmapFactory, then local Tesseract; no OCR boxes or original-image character offsets are claimed. WAV input must be 16 kHz, mono, signed 16-bit PCM, 0.1–15 seconds. Other audio formats are rejected rather than silently converted. Only English recognition is qualified, and even that is limited development evidence: a real stylized STOP photo returned no text. Names, numbers, accents, noise and poor images can be wrong. Empty results remain empty. There is no camera capture UI or general scene understanding.

The preview receipt identifies the original URI/input SHA, recognized UTF-8 SHA, exact recognized-string UTF-16 range, engine revisions and asset hash. Editing adds a separate reviewed-text hash. Microphone recordings are held only for processing and are not saved; selected original files are not copied into the document library. Personal-input ownership does not imply public redistribution rights. Saved/history/bookmark/reader/export ownership is unchanged.

## Rig reproduction

Use the installed Android toolchain configured by `tools/android-build.sh`. For a new checkout, explicitly fetch pinned native sources with `python3 tools/attachments/prepare.py --fetch`; ordinary builds only verify local sources. To provision optional test weights, run `python3 tools/attachments/prepare.py --fetch --models` (or the pinned Hugging Face CLI download recorded in the evidence). Downloads remain ignored. Never substitute a newer revision under the same filename.

Run `bash tools/android-build.sh`. The build compiles both ARM64 and x86_64 libraries serially with two build workers, using installed NDK r27c, CMake and static CPU-only components. The final JNI library hides internal ggml symbols to coexist with the research runtime. Full engine/model notices are packaged under `assets/licenses/attachments`; source revisions/archive hashes are in [sources.json](../tools/attachments/sources.json).

For public development checks, recreate controls using the already pinned task330 Pillow environment: `downloads/documents-tools/bin/python tools/evaluation/attachments/fixtures.py`, then `downloads/documents-tools/bin/python tools/evaluation/attachments/photo_fixture.py`. The latter explicitly fetches the separately pinned CC0 photo only if absent. The original fixture manifest is preserved and the photo is a separate supplement.

`bash tools/evaluation/check_attachments.sh` builds/installs the APK and test APK on existing emulator-5560, exercises real JNI and UI controls, saves a unique ignored run directory, and fails on behavior or asset integrity errors. It requires the existing saved model/library to verify retention and changes microphone permission only for this app. It does not reset devices or services. The fixture copies add about 82 MB of test-only storage and are separate from installed optional weights. `python3 tools/evaluation/attachments/budget.py` is the additional current-candidate coexistence check on existing full-catalog emulator-5562; it requires the attachment test APK built by the main check and all 31 retained shards. It neither downloads nor recopies the bulk corpus.

Physical microphone acoustics, ARM64 execution, GrapheneOS, current API37 execution, broad OCR accuracy and multilingual support remain unqualified. ELF and ZIP 16 KB alignment are static checks, not substitutes for API37 loading evidence for this new library. Native model initialization and Bitmap decoding have no immediate cancellation callback; bounded inputs, post-stage checks and native decode callbacks limit work, but no universal cancellation deadline is promised.
