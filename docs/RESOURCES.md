# Resource policy and recovery

PocketLore uses one resident native session, one request context and one sequence per process. Closing during an active call cancels it; the resident lease remains held until that call returns and finishes context and model destruction. A second session is rejected while that lease is live. Each request has a fresh 2,048-token context, a 256-token output cap, a 2,048-token batch and a 128-token microbatch, using two CPU threads and FP16 K/V storage. Context and sampler memory are freed on success, failure and cancellation; no persistent prompt/KV cache is written.

Generic model files must be regular and at most 2,048 MiB; their model-buffer cap remains 2 GiB. One explicit experimental Qwen3-4B profile permits exactly 2,497,280,256 bytes with SHA256 `7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`, after complete cancellable identity verification, and a separate 4.6 GB model-buffer cap. It does not change selection or admit unknown larger models. Simulated allocation preflight precedes weight loading, and actual accounting is checked again after context allocation. KV and compute caps remain 768 MiB and 1 GiB. The pinned profile must additionally fit measured available/total memory with full file bytes, simulated buffers, a 512 MiB app margin and 1 GiB OS reserve. These checks cannot prevent every allocation-time OS kill or prove arbitrary-model safety. Native counters are not process memory totals; the accounting uses the immutable runtime pin and requires review when that pin changes.

On Android memory-pressure callbacks, PocketLore cancels the current native operation, discards unverified answer text and queues model release behind the operation. Saved model/source files remain. The user can choose **Reload saved model**, or **Unload model to free memory** manually. A failed Java allocation in model import or generation releases resources and reports failure instead of publishing a partial draft. Android may kill a process without callbacks; reloading after restart is still necessary, and this policy does not establish survival of true system OOM.

Model staging is serialized across Activity recreation. Pack import runs on a separate shared serial worker and installation is synchronized. Pack data is streamed to a bounded stage, then verified/indexed before atomic replacement. This avoids the former additional full archive copy. Cancel pack import or memory pressure cancels the copy and prevents promotion; validation also responds to thread interruption. A blocked document-provider read may delay cancellation. Free storage must cover the model's declared size, or the pack's conservative 16 MiB maximum, plus **256 MiB** reserve. Existing originals remain at their provider; old installed and new staged copies coexist until promotion.

Only `model.partial` and `pack-[digits].partial` in app files are eligible for orphan cleanup, on the corresponding serialized worker. Installed files, unrelated partial files, research data and system-managed caches are retained. Stage files are deleted in failure/finally paths, including the tested injected Java allocation failure. No arbitrary cache-directory deletion occurs. The application writes no persistent index or inference cache; Android-managed code/cache storage remains part of disk accounting.

The intended <=12 decimal GB device allocation and conservative <50 GB disk plan are specified in [measured evidence](evidence/resources.md). They are engineering budgets, not physical acceptance. The tested emulator is approximately 2.59 GB and swaps; rig host memory is reported separately. Normalized/synthetic resource-control tests do not replace physical pressure, thermal, long-session, large-pack or diverse-model measurements.

## Reproduce

Provision the documented pinned runtime/toolchain, pack and travel source caches first. The existing isolated emulator must be booted. The resource check reuses the pinned Qwen3 model and reference pack in `files/synthesis-tests/` from the synthesis setup, and a saved app model in `files/model.gguf` from answer integration. It verifies the Qwen3 and pack hashes before testing. It does not download, replace the user's model, start an emulator or alter services.

```sh
bash tools/android-build.sh
bash tools/evaluation/check_resources.sh
```

The resource test makes one full temporary copy of the 1.83 GB model in an isolated app test directory; at least its size plus 256 MiB of free device storage is required. It removes that stage and preserves installed files. Small labeled test sentinels and raw reports remain as evidence. Outputs are under ignored `downloads/resources/run-*`. The script fails for missing dependencies, failed behavior assertions or JNI errors and preserves available outputs. Runtime generation here is a resource workload, not an evaluation of citation support or answer quality.

## Task420 reservation contract (supersedes instantaneous checks for listed paths)

A process-wide synchronized `ResourceStorage.Ledger` reserves a declared incremental peak before covered staging. Each admission resamples current app data plus base/split APK and extracted native libraries, using the greater of logical and allocated bytes per inode; hard links are counted once. Unknown/unreadable usage, unsupported symlinks, arithmetic overflow or traversal beyond200,000 entries refuse admission. Only the platform-declared native-library symlink is resolved. The app has no separate manifest processes; this is not an interprocess or platform-wide reservation service.

Projected covered bytes = measured current usage + all outstanding reservations + requested peak. Above50,000,000,000 bytes refuses as hard cap; above45,000,000,000 refuses until assets are removed/reallocated. Exactly45GB is allowed;50GB is not an alternative permission to exceed target. Available space must independently cover all outstanding/requested bytes plus268,435,456 bytes OS reserve. That unallocated reserve is not counted as installed app content. Bytes already materialized while a reservation remains open can be counted twice intentionally; this is conservative, not a utilization optimizer.

Covered paths: model copy and its outer load/promotion transaction (nested reservations conservatively charge twice); optional OCR/speech asset staging through atomic promotion; PackLibrary archive plus twice256MiB database allowance (one for possible journal) plus16MiB validation/catalog allowance; personal conversion with16MiB disk allowance. Each stage also reserves1MiB directory/metadata headroom. Declared payload limits remain enforced by existing copies/parsers. AutoCloseable/finally releases tokens on success, exception and cancellation; cleanup precedes outer release. Process death clears in-memory tokens, while abandoned stages remain in the next measured baseline and existing owned recovery rules apply. Tokens are not persisted approvals.

This is bounded admission, not universal allocation interception. Current data/index/cache/notebook/rollback bytes inside the app directory are measured, but subsequent unreserved writes, bulk ScaleLibrary/SharedShardUpdate paths, reader decompression/cache, notebook/export snapshots, package-manager compilation outside app data and external provider copies remain incompletely reserved. Provider-owned usage is unknown, not zero. One MiB metadata headroom and database journal allowance are conservative estimates, not measured full update peaks. Filesystem races can fail measurement closed. External consumption after sampling can still cause ENOSPC; existing rollback remains necessary. No whole-device50GB,12GB RAM, network traffic, rights, quality or physical-device guarantee follows.

See [task420 evidence](evidence/storage-reservations.md) for the six frozen host fixtures, exact build identity and historical capacity separation. No device suite or inference was run for this bounded contract.
