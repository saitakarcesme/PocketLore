# Personal documents and portable collections

Open **Personal documents and collection export** from the library. Enter an owner/author statement and a source date (or leave Unknown), then choose a local document. Import finishes before it becomes a searchable active collection. Use the existing **Choose collections** and **Remove a collection** controls to enable, disable or delete editions. Removing a collection does not delete its original file in the document provider.

Supported inputs are UTF-8 TXT/Markdown, comma-delimited CSV with quoted commas, doubled quotes and multiline fields, strict JSON with nested scalar values, and text PDF on Android 15/API35 or later. Markdown remains source text; CSV records remain exact serialized records with field headers; JSON pointers accompany exact serialized values (escaped text is not a separate decoded search field). CSV rows must have consistent widths. Empty/scanned/image-only and password-protected PDFs are rejected with an explanation; no OCR or password cracking is performed. On older Android versions, convert PDFs locally to UTF-8 text first.

The limit is 4 MiB per original file, 500,000 extracted UTF-16 units, 1,000 passages, 20,000 units per record/block, 100 PDF pages and 32 JSON nesting levels. Existing combined-library admission still applies: eight collections, 16 MiB retained small-pack archives/expanded content, 1,000,000 active text units and 200,000 token entries. A separately admitted broad edition is not exportable through this bounded workflow. A large or complex PDF can still stress Android's native renderer before text limits are known; these limits are not a hostile-PDF memory proof.

Source inspection shows original filename/location, ownership statement, source date, device-clock import date, raw/extracted SHA256, extractor identity, and exact UTF-16 `[start,end)` offsets in retained `text.txt`. PDF page/block numbers refer to Android extraction order, which may differ from visual layout; these are not PDF byte coordinates. Every portable import regenerates the expected text/spans from its original bytes and rejects discrepancies. Android-version changes may alter PDF extraction and reject an otherwise genuine exported PDF collection; its original bytes remain available in the ZIP for local reimport.

**Export a portable collection** creates a `.plpack` ZIP containing `personal.json`, `original.bin` and `text.txt`, or exports an existing supported small collection unchanged. This explicitly exports private original content, owner and source-location metadata. Hashes detect accidental changes, not publisher authenticity, truth or redistribution permission. The application does not infer public rights for personal documents. Reimport the `.plpack` using **Import knowledge pack**; the same exact bytes retain the same edition hash and source links. Do not edit the archive or use it as an authenticated signature.

Cancel import/export using **Cancel operation**. Pollable provider pipes are checked at 50 ms intervals, with descriptor closure after cancellation. Provider acquisition/open IPC, regular-file/FUSE stalls and an individual native PDF parsing call can require platform/provider cooperation. An unsuccessful export attempts to remove the new destination and otherwise warns that a partial file may need removal. Retained catalog/model files remain unchanged on failed imports. Export selection, owner and date survive Activity recreation; interrupted extraction restarts from the chosen file rather than resuming midway.

## Integration with the UI lane

`PersonalDocumentsActivity` owns only document ingestion and portable collection export. Its single entry point returns to the existing library, which reloads the durable `PackLibrary` catalog. Saved/history/bookmarks, notebook export and the source-reader design remain owned by the UI refinement lane; no lane files or services were modified. That lane should route its personal-import control here and preserve the metadata/UTF-16 contract when refining collection names and reader layouts. Current generic collection selectors display edition IDs/hashes; friendly filename labels are a remaining presentation refinement.

All extraction, indexing and search run locally. The APK has no INTERNET permission or Google Play Services dependency. A local-only document-picker request does not control the implementation of every third-party document provider; choose previously downloaded local files. Personal retrieval is not evidence of supported generated answers.
