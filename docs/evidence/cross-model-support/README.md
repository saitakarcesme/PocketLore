# Separate-model support experiment — declaration

Task500 repair2 reuses all12 actual Qwen3 4B drafts from task500 and their exact frozen source pairs. It does not regenerate old answers. Six new constructed paired probes were frozen before the verifier call: supported versus absolute assembly correspondence, supported ventilation versus an invented numeric tail, and negative versus positive imaginary-unit square. These are tests, not corpus facts or held-out evaluation.

The materially different experiment uses the existing independently trained Qwen2.5 7B instruction artifact as a whole-answer verifier, not a Qwen3 self-audit or the old finite rules/NLI threshold. It is still a fallible model from the same organization/family. The exact system prompt and parser are in Android-compatible CrossModelSupport.java. One greedy call per record uses4096 context and512 verification tokens; entire source paragraphs and the entire preserved draft must fit without truncation. Errors, cancellation, output-budget exhaustion or malformed verdicts are invalid. Successful first-line parsing does not prove entailment.

The model is the already licensed/pinned7B GGUF, SHA65b8fcd92af6b4fefa935c625d1ac27ea29dcb6ee14589c55a8f115ceaaa1423. Exact runtime and weights are checked before execution. Six CPU threads, one process,12GB virtual-address hard bound,11GB sampled RSS stop and12GB available-host-memory admission are retained. No model downloads, device inference or services are involved. Production UNAVAILABLE is not replaced by model confidence. All provisional approvals require independent complete-prose/source inspection and the zero-unsupported gate before any qualification decision.

Both generator and verifier weights would be needed for an offline two-model product; sequential unloading avoids concurrent model RAM but not combined disk cost. Historical full inventory replacing the0.5B baseline with both models gives48,317,556,832bytes before later asset/code changes; historical shard-update allowance becomes51,485,166,131bytes, above the50GB hard cap. These are planning arithmetic from the preserved303 baseline, not current measurements; no sources are dropped to conceal the overflow. A successful verifier experiment alone therefore cannot qualify the complete distribution or the4GB Android environment.
