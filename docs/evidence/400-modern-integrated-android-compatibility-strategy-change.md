# Task400 strategy change: diagnose the teardown boundary before another suite

Three prior approaches produced builder passes followed by failed required runs: sequential per-file collection, package restoration plus fresh replay, and batched collection with early font restoration. Their historical successes cannot explain recurrent device loss immediately after instrumentation. Latest run20261002T023803Z-96ed2e58 completed default UI instrumentation in39.815 seconds, then collection/restoration encountered an offline device. The failure remains a whole-run failure.

The materially different approach is diagnostic-first: examine only the tested emulator's crash/exit telemetry and reproduce the lifecycle boundary with a small instrumentation probe before selecting a compatibility fix. Do not merely retry all six phases or infer an OOM/timeout from missing transport. Separate application assertions, UiAutomation/runner teardown, adb transport and kernel reboot observations. Preserve original raw command results and device boot identity. Do not change emulator/services, GPU, private orchestration or model settings.

Discriminating checks: an actual crash signature must support any causal claim; a minimal control must differ only in the implicated test mechanism; production app/APK/model identity remains fixed; the complete fresh API37 behavioral suite must still pass with exact invocation and transport identity, original font readback, unchanged boot ID and current screenshots. A small probe is not a substitute for full behavior. If the environment cannot support the boundary, retain an honest failing gate and exact external dependency rather than another unsupported passing report.

Initial emulator crash telemetry contains repeated UWB HAL startup aborts for absent/dev/uwb0, and no system_server_crash entry. This does not establish the cause of prior disconnects and does not authorize service changes. The revised design is a device-owned instrumentation transaction: restore the original font while UiAutomation is still alive, then stream a bounded hash-manifested evidence snapshot through instrumentation status before finish. Host-side post-finish report/screenshot extraction is removed. A minimal no-UI versus UiAutomation teardown control precedes the complete suite. Failed transport, missing chunks, wrong run ID, failed restoration, changed boot or incomplete claims still fail; streaming is not a waiver for rebooting hardware. App source and production APK remain unchanged.
