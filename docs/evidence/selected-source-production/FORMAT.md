# Provisional selected structure v2

This is a separate host preparation format, not a ready-pack format accepted by the legacy Android importer. The recovered Android v1 reader requires a separately verified v2 provider before production routing. No inference admission follows from this index.

`originals` contains one sequence disposition for every position through the frozen inclusive prefix. `revision_bindings` detects differing hashes for the same page/revision even if that revision is superseded. Any conflict or unverified metadata blocks the page conservatively. `latest` selects highest revision, with earliest sequence for identical duplicates. `selected` joins the pinned priority database by page ID; descending views and ascending page ID determine order. A refused selected original is retained, never replaced to reach a count.

Source snapshots are read-only, query-only, mmap disabled and 2 MiB cache, with at most 256 detached metadata rows per transaction. Original bodies use sequence primary-key lookups only after 16 MB compressed/uncompressed size admission. A later source metadata rebind covers the entire prefix. The ranking file is hashed before and after use. Exact hashes do not certify append-only behavior outside the observed prefix.

Original JSON is present offline in 32 KiB byte chunks. Original HTML is present offline in at most 8192 UTF-16-unit chunks, without splitting Unicode scalar values. Typed structure capsules contain at most 128 nodes and a 262144-byte hard maximum. A content-addressed capsule stores SHA256, uncompressed size and zlib-compressed bytes. Piece ranges are half-open byte offsets for JSON, UTF-16 offsets for HTML and node ordinals for structure. Individual original/HTML/metadata identities survive reconstruction. Full HTML remains inert data, never executable WebView markup.

Contexts retain exact original HTML ranges, fragment hashes, source title, reconstructible literal/entity text and enclosing node ranges. Tables, captions, cell headers, math, quotations and references remain in the original and typed tree. Structural context is not a formula interpretation, attribution clearance, or evidence of entailment. Plain prose remains pending independent rights/support review; complex contexts are inspection-only. No context is independently admitted by this producer.

An article, its capsules/contexts, receipt and selected disposition commit in one explicit transaction. Cancellation rolls the transaction back. Metadata batches commit independently. Explicit resume requires identical executable/configuration and a stopped metadata/materialize phase; completed/finalization outputs cannot silently replay. No automatic retry exists. A frozen fixed prefix cannot claim final latest revisions; a new complete-source finalization must reconcile every disposition and whole archive/stage identity before full admission.

There is no VACUUM or body duplication in FTS: FTS4 uses external content from `contexts`. Literal context projections can overlap (for example list item and paragraph); their storage is measured separately. Original JSON itself includes HTML, so JSON plus separate HTML/structure is deliberate fidelity duplication, not claimed optimal final distribution storage. DB pages, free pages, capsules, FTS and temporary/journal files are measured; small-run measurements are not whole-device/update peaks.
