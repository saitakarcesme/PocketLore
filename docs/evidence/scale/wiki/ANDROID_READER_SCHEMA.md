# Encyclopedia reader contract: SQL schema 3

This describes the actual Linux staging producer and Python reference reader. It is not an Android implementation or compatibility result. PocketLore's existing FTS4 importer needs a new adapter and SQLite with FTS5; silently substituting the platform FTS implementation is invalid. Android, GrapheneOS, physical memory, useful generated answers and distribution acceptance remain open.

## Edition and source identity

Installed files are each shard's `catalog.sqlite`, `articles.blocks` and `measurement.json`, plus root `redirect-aliases.sqlite`, root JSON provenance/inventory, NOTICE and offline license texts. Progress, writer locks, journals, source Parquet, priority databases, receipts and rejected editions are staging assets. The sealed inventory names the exact installed set and byte total. Reject missing or hash-mismatched installed files before activation. The host reader checks fetched blocks and records but does not implement an Android installer or signature trust root.

FineWiki is pinned at `8bd13e72e6a002407649b3e898535f42ceb1aeb9`; per-shard configuration binds its Parquet SHA-256 and the canonical-priority database hash. Stable identity is dataset revision, Parquet hash, zero-based source row, page ID and article revision. A live canonical URL is not the pinned version. Revision URL: `https://en.wikipedia.org/w/index.php?oldid=REVISION`. Attribution history: `https://en.wikipedia.org/w/index.php?title=URL_ENCODED_TITLE&action=history`.

Canonical selection chooses the highest revision per page ID, with source shard/row ties ascending, then resolves competing titles by revision and page ID. Invalid latest records are excluded without substituting an older version. Priority comes from the pinned NeuML precomputed pageviews table: spaces become underscores, followed by Unicode lowercase, with literal matching. Its aggregation interval is unknown. Missing views remain NULL, not measured zero. Read the actual full count and priority hash from final provenance; do not infer them from the original sizing target.

## SQLite tables

`articles` columns in order are `id INTEGER PRIMARY KEY`, unique `title`, `url`, `revision`, `modified`, `tier`, nullable `views`, `offset`, `length`, `raw_length`, binary `sha256`, binary `text_sha256`, binary `wikitext_sha256`, `has_math`, `source_row`, `rights`, and `block_id`. Checksums are 32-byte SHA-256 values. Dates and revisions are source facts, not acquisition dates. Tier is exactly `full` or `lead`.

`blocks` holds `id INTEGER PRIMARY KEY`, file byte `offset`, compressed `length`, inflated `raw_length`, and binary SHA-256 of the inflated block. Article offsets instead address UTF-8 byte slices **inside the inflated block**. Article length equals its raw length. The block is concatenated JSON records, without separators or a custom binary header; exact slice boundaries define each record.

`search` is positional, contentless FTS5 with `title`, `body`, tokenizer `unicode61`, and rowid equal to page ID. The final `reader_stopwords_v1` index body omits the same 28 words already ignored by the reader query parser; stored tier text and titles remain unchanged. Older `verbatim` prototypes indexed retained text directly. The index policy and producer hashes are bound in each shard configuration. `terms` is disk-backed `fts5vocab(search,'row')`, exposing term/document/occurrence counts. No embedding table exists. Local `aliases(alias,target,kind)` contains normalized titles, not a fabricated redirect inventory. `exclusions` preserves source rows and reasons. `checkpoints` binds configuration and recovery offsets.

The separate root redirect database has `aliases(alias,target,shard,fragment)` with primary key `(alias,target,fragment)`, WITHOUT ROWID. Direct aliases come from the 2026-09-01 primary Wikimedia title/redirect dumps. Target ID **and exact title** must match selected FineWiki. The alias snapshot is newer than the text; chains and missing targets are excluded. A fragment is source metadata and does not prove an installed section exists. Alias normalization is underscore-to-space plus Python Unicode casefold; Java lowercase alone is not equivalent; the measured Python casefold data is Unicode 15.0.0.

## Lazy decompression and payload

Seek/read the block exactly, inflate its RFC 1950 zlib stream, reject trailing input, incomplete streams and mismatched lengths/hashes, then validate the article slice and its hash. Maximum admitted raw block is 128 MiB; maximum compressed block is 64 MiB. Producers group at most 64 records with an 8 MiB raw target; oversized single records can exceed that target within the hard limit. The reader caches at most two blocks of at most 8 MiB each; larger blocks are decoded but not cached. These limits do not constitute total-process memory acceptance.

JSON contains `text`, `wikitext`, `wikitext_scope`, `wikitext_ranges`, `infoboxes`, source text/wikitext hashes, article revision/date/URL, tier, notice status and a change description. `wikitext_sha256` in SQLite authenticates **the retained field**, while `source_wikitext_sha256` authenticates the full original in pinned Parquet. Ranges are Unicode codepoint half-open offsets `[start,end]` in the original wikitext; join those slices with two newline characters to reconstruct the retained supplement. They are not UTF-8 byte offsets.

The final candidate designates 1,250,000 full articles and 5,248,498 leads; this explicitly reduces the original 2–3M full target after oversized measured shards. Full-tier text is byte-identical to FineWiki extracted text. A lead is the entire prefix before the first Markdown level-two heading, with trailing whitespace normalized to one newline. If no such heading exists, the whole extracted text stays but the tier remains explicitly `lead`. Leads are never presented as complete articles. FTS indexes retained text, not archived full bodies or wikitext supplements.

## Supplement policies and rights

Read `checkpoints.config.supplement`; schema number and edition name are separate. Preserved schema-1 pilots used one zlib stream per article and hexadecimal checksums. Shared-block schema 3 supports multiple supplement policies; no decoder may assume every supplement is complete original wikitext.

The current `lean` candidate scans every original wikitext. It retains unknown templates, recognized notice prose, mathematical/chemical context, and unit/math templates, including nested templates within omitted ordinary containers. Known citation and infobox boilerplate is omitted unless explicit permission/copyright/attribution/license fields override omission; source structured infobox fields remain. Ambiguous braces or math tags, flagged source math without recognized markup, and broad notice-screen candidates that otherwise produce an empty supplement retain whole wikitext. Each actual scope is explicit, including no detected supplement. Original archives remain preserved outside the installation. This extraction does not expand templates, reconstruct missing equations, or establish completeness of notice detection.

FineWiki identifies its processed release as CC BY-SA 4.0 and mentions Wikipedia GFDL availability. Recognized unresolved copyright/permission markers and missing required metadata are excluded. Unknown source-specific rights remain unknown; heuristic screening and exact range retention are not independent rights clearance. NeuML's card gives CC BY-SA 3.0/GFDL for its dataset but no separate database declaration; underlying Wikimedia Analytics is identified as CC0. Attribution, license copies, change notice and article history/revision links remain inspectable. This is evaluation staging, not a distribution-ready rights assertion.

## Retrieval, recovery and measurement

The host reader opens completed shards immutable/read-only, 4 MiB SQLite cache per shard, mmap disabled. It takes up to 16 unique non-stopword query tokens, reads term statistics from disk, retrieves up to 12 BM25 candidates and four exact title aliases per shard, plus at most eight exact redirect targets, then lazily decodes candidates and reranks using global document frequencies. Python tokenization/casefold differs from SQLite unicode61; this is a disclosed retrieval limitation. No lexical hit proves support, absence, synthesis quality or entailment. Absence controls measure hits; answer abstention is not implemented in this tool.

The exact query/body token pattern is Python Unicode `[^\W_]+`, followed by casefold. The 28 ignored query words and index-body omissions are `a an the is are of to in and or for from with what how why which when does do by on at as into explain compare between`. Query terms retain first-occurrence order; FTS uses quoted terms joined with `OR`, local `bm25(search,5.0,1.0)` and a 12-row limit. The final reference ranking, including exact-alias bonus, global document-frequency weighting, length normalization and page-ID tie-break, is implemented in the sealed `reader.py`; an Android adapter must not describe platform-default ranking as equivalent without comparison.

Builders use per-shard writer locks, 64-row Arrow output batches asserted below 2 GiB, disk temporary storage, 256 MiB SQLite cache for the initial two shards and a documented 768 MiB cache for later child starts, zero auxiliary SQLite sort workers in the final producer, and at most two CPU workers constrained to CPUs 6 and 12. Decoder buffers also consume memory. Block fsync precedes checkpoint commit; orphan tails are preserved before recovery truncation. Changed configuration requires a new edition. Completed caches are never overwritten. Indexes are optimized and vacuumed before measurement/sealing.

`measurement.seconds` is accumulated committed build-loop time, excluding lost interrupted work and final compaction. Fresh child execution receipts include subprocess wall time and final checks; parent priority hashing is separate. Migrated shards additionally report reblocking wall time/RSS; inherited original build metrics are not migration metrics. RSS is Linux process `ru_maxrss` in KiB, not host total, Android PSS or physical acceptance. Query latency includes FTS, decompression and ranking but excludes subsequent source-audit excerpt reads and inference. It is one host pass with uncontrolled OS cache (no cold-cache reset) and shared-host contention; intervening source reads may warm later queries. Full file inventory checks occur at sealing/admission, not on every search.

## Selected alias schema 2

The selected lossless normalization stores repeated shard filenames in `shard_names(id INTEGER PRIMARY KEY,name TEXT NOT NULL UNIQUE)`. Its `aliases.shard` is an INTEGER reference; all other alias columns and the primary key are unchanged. Join `aliases a JOIN shard_names n ON n.id=a.shard` and use `n.name` as the original shard filename. The reference reader supports both layouts. `compact_aliases.py` checked all 10,100,398 reconstructed tuples against the preserved parent, with zero mismatches and SQLite integrity passing. The selected database is 403,890,176 bytes, SHA-256 `a691091bc7892155a4e6381d322070076dd6a6064b7a2a23be99e95898b76a12`; this normalization does not reduce alias coverage.
