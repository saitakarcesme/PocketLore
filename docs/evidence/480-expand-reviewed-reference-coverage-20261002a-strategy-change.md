## Materially different execution design

Stop the compile/check/document retry cycle. Preserve the frozen edition, cases, model selection and source review. Resolve exclusive device ownership first, then execute the real Activity/provider import and source-brief paths with an invocation-specific immutable evidence directory. Capture every phase result and transport failure immediately, before any semantic assertion can terminate the collector. Preserve partial raw receipts even when a later phase fails; a subsequent run must have a new identity rather than overwrite an earlier failure.

The change is in evidence acquisition, not source selection, question routing, answer gates or evaluation thresholds. Host output is never a substitute for installed Android behavior. No amount of collector work establishes the missing device gate. The authorized runtime state currently records only an older installation and grants no exclusive lease. An explicit ownership request is pending; no device command is authorized until the response or a valid coordinator receipt arrives.

## Discriminating checks

1. Before any device command, validate a new exclusive, unexpired emulator-5564 lease; fail without changing device state if absent.
2. Bind source/build inputs and run-owned APK copies, installed production/test identities, boot/settings, retained assets and the exact expanded pack.
3. Preserve partial stdout and stderr for transport timeout or process failure; decode and hash-bind any reported phase receipt before assessing success. A failed invocation remains failed.
4. Exercise normal app import, exact source/citation reading, Back, export/cancellation and reopening. Inspect actual Android quotations and relevance/completeness over the unchanged public development cases.
5. Reconcile independent app/package/provider byte observations and actual staging reservation samples; retain limitations on continuous peaks and full-device accounting.
6. Run the three required checks against the new immutable evidence only. Missing phases, stale identity, corrupt bytes, boot/settings drift or incomplete source review must fail. No completed HANDOFF without these receipts and supervised review.

Instrumentation transport failure no longer prevents an attempt to retrieve the actual phase JSON/screenshots. Only after retrieval does the collector assess the original transport result; a nonzero exit or timeout still fails. Every invocation retains its separate seal. Four local subprocess controls passed; log and hash receipt are in `reference-coverage-expansion/strategy-change/`. They exercise transport preservation, not Android or answer behavior.

The source edition, public development cases, original source packets and all prior failures remain unchanged. No lease was received during this work, no device commands were run and no Android check was relabeled as passing. A collector change cannot resolve ownership; the next action remains the explicit coordinator lease followed by actual bounded device validation.
