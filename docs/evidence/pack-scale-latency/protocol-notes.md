# Public scale/latency protocol

Frozen in 058aba7 before execution. The original pack is the licensed 186-passage English reference edition, SHA-256 567e9bbbaab896826809ec20f81ae1c4b3f421b011931edae0989d28cfce10ea; its manifest preserves USGS, NPS and National Archives attribution. The exact same factual text is repeated under explicit stress-only document IDs. These packs are not a corpus, broader source diversity or increased factual coverage. All generated ZIP assets remain ignored.

Scale cases use 1, 5, 20, 50, 74 and 75 copies: 186, 930, 3,720, 9,300, 13,764 and 13,950 passages. The first five are expected to import; the sixth exceeds the 2 MiB manifest bound. Archive and combined expanded bytes remain below 16 MiB; document and passage counts remain below 1,000 and 20,000. Thus the manifest cap is the active boundary for this document mix, not a universal maximum corpus size. The supported boundary is tested at whole-source-copy granularity (74 copies), not every byte below each cap.

Every scale case starts in a distinct app process, loads the real pinned demo model and old 186-passage index, then installs into an isolated app-owned directory. The old live index is deliberately retained through validation and atomic replacement. Post-import snapshots request GC; no guarantee of collection completeness is made. A process PSS or used-heap delta includes allocator/runtime behavior and is not exclusive index-object allocation. Logical vocabulary/posting/text counts are reported separately. New-index-only snapshots release the old reference. Large-to-large replacement, unrelated apps, diverse vocabulary and device-wide memory pressure are outside this bounded transition.

Latency uses the saved Qwen2.5-0.5B Q4_K_M GGUF (491,400,032 bytes), SHA-256 74a4da8c9fdbcd15bd1f6d01d621410d31c6fc00986f5eb687824e7b93d7a9db, and two exact frozen public questions. One warm-up request is retained but excluded from percentiles; ten subsequent requests use the same process and loaded model. Five process-cold requests use distinct newly started app processes and fresh native sessions. OS/filesystem caches are not flushed. The runtime recreates native contexts per request; warm does not imply cached prompt/KV reuse.

Nearest-rank p50/p95 are sorted values at ceil(p*N)-1, with no interpolation; for five cold samples p95 is the observed maximum. Pack load, model load, retrieval, request first-token and request-total times are separate. Request time begins before retrieval and ends at AnswerEngine return; it excludes model/pack load. Cold ready-to-result begins at instrumentation onStart, includes load/setup, and excludes Android instrumentation-launch overhead. Whole instrumentation wall time is retained separately and includes teardown/reporting. First token is an unverified draft callback, not first useful supported content. GENERATED, FALLBACK and ABSTAINED routes must remain distinct, with raw drafts preserved.

Memory sampling targets 250 ms using Debug PSS and /proc/self/status RSS, VmSwap and VmHWM plus Java used/max heap and native buffer counters. Sampling overhead is included in timings, intervals are not guaranteed, and maxima may miss short peaks. VmHWM is process-lifetime RSS high-water, not phase-specific PSS. Stage/saved-file sizes are sampled logical bytes, not allocated-block storage peaks or provider footprint. Host and emulator /proc/meminfo are separate artifacts. No host values may be relabeled as phone memory.

No production admission threshold or retrieval/generation implementation was changed to fit these tests. A harness compile failure on an unavailable swap-PSS API is preserved separately; /proc VmSwap supplies the supported swap observation.
