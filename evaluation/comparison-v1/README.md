# Comparable development evaluation, version 1

The five exact questions are inherited unchanged from the already frozen public synthesis development set. They are familiar development material, not unseen evaluation. The protocol hash is pinned in `tools/evaluation/verify_comparison.py`; changes require a new protocol version and measurements. Private holdout is never opened by these tools.

Run `python3 tools/evaluation/run_comparison.py` on LLMRig with the existing `emulator-5560` booted and airplane mode enabled. The emulator must already contain the imported Qwen2.5-0.5B model matching the protocol hash at app-private `files/model.gguf`. The runner refuses other models instead of replacing them. The licensed reference pack must be cached at `downloads/packs/english-reference.plpack`; use the existing pack build/import documentation to provision it. All downloaded models and run artifacts stay ignored. No external provider keys are requested.

The runner adds instrumentation from `tools/evaluation/comparison` with a Gradle init script; it does not change application sources. It builds/installs existing app code and a dedicated test APK, uses real production retrieval and JNI AnswerEngine, and compares against the production deterministic retrieval response. This baseline is not a separate commercial rival. Both systems receive identical questions and the same complete corpus. Retrieved sources must match exactly. PocketLore performs its normal context selection, support checks and fallback; the baseline prints retrieved evidence. Different response lengths and computation are intentional system differences, not equal token budgets.

All ten responses run sequentially on the same CPU emulator, alternating which system runs first. This is a single exploratory pass, without warmup or confidence intervals. Pack/index and model loading are recorded separately. End-to-end request timing includes retrieval through final answer construction, excluding UI, import, setup and JSON recording. `first_token_ms` is AnswerEngine's model-stage measurement, not end-to-end time to first token; baseline zero means not applicable. Model residency and OS caches are shared; there is no controlled cold-start or thermals experiment.

Raw drafts, published answers, exact generation prompts, runtime identity, source text/IDs/dates/licenses, artifact hashes and timings are preserved. `python3 tools/evaluation/verify_comparison.py PATH` validates a run and rejects deliberately damaged question, source, timing, generation and citation records. The default PATH is the checked-in evidence run. It cannot establish semantic support from citation syntax, prove that a forged report came from a device, or replace independent review.

Give reviewers **only `blind.json`**, not `identity-key.json`, raw results, timing, manifests or this system description. Review correctness, support, completeness, uncertainty and citation usability; ratings are initially null. The packet has opaque shuffled answer labels and preserves answer/source text verbatim. Extractive wording may reveal system style, so blinding is imperfect. No reviewer ratings, winner or superiority claim are supplied. External frontier/web comparisons need a named authorized endpoint, reproducible configuration and separately defined network/source conditions; they remain unrun. Release holdout requires a separate frozen release evaluator.
